Replacing the job queue

A proposal, three decisions, and a draft announcement. Select any text to comment on it or suggest a change.

Move the job queue from Redis streams to SQLite in WAL mode. It removes our only reason to run Redis, and load tests keep p99 enqueue latency under 5 ms at three times today's peak.

Draft announcement

Starting November 4, background jobs run on a SQLite queue stored next to each service instead of the shared Redis cluster. You do not need to change anything: the enqueue() API is the same, and existing jobs drain before the switch.

The main visible difference is that a Redis outage no longer stops job processing. Enqueue latency drops slightly, from about 11 ms to about 4 ms at p99, and jobs enqueued in the same transaction as a database write are now committed or rolled back together with it.
