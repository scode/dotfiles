Build cache rollout, week 12

Where the remote build cache stands after twelve weeks, and the two decisions it needs from you.

Cold builds are down from 14.2 to 8.7 minutes (39%). The remaining cost is almost entirely the proto-gen step, which the cache cannot help with until its outputs are deterministic. I'd like a call on two open questions before starting phase 3.

What changed this week

Most of the gain came from finally getting the test fixtures out of the action key. They were hashed as inputs to every test target, so touching one fixture invalidated all 1,400 test actions rather than the dozen that read it. Press Shift+M on the build dashboard to see the per-target misses: they used to jump in lockstep with fixture edits. The old workaround (pinning fixtures to a release tag) is gone.

  • Fixture hashing is now per target, keyed on the files a target actually opens.
  • Cache eviction moved from LRU to size-weighted LRU:
    • large link outputs are evicted first;
    • small compile outputs, which are the hit-rate workhorses, survive about 3x longer.
  • CI now uploads on main only. Branch builds read but never write.

The rollout order was:

  1. Read-only cache for CI.
  2. Read-write for main.
  3. Read-only for developer machines next

Terms

Action key
The hash of an action's command line, environment, and input files. Two actions with the same key are assumed to produce the same outputs.
Cold build
A build with an empty local cache. The remote cache may still serve it, which is the whole point.1
Why not just use a bigger CI runner?

We tried. Going from 16 to 32 cores took the cold build from 14.2 to 11.9 minutes, and the runner costs twice as much. The cache got further for less money, and it also helps developer machines, which a bigger runner never will.

Open questions

  1. Should developer machines get write access, or read-only?

    Write access makes the cache warmer for everyone but means trusting outputs from unmanaged machines.

    Read-only
  2. Is a 200 GB cache quota acceptable?

    At the current eviction rate, 200 GB holds about two weeks of compile outputs.

    Yes, revisit at week 16
