# Add a lore entry

Read `SKILLETTE.md` in this directory first if it is not in context; the naming and orientation rules are in its
canonical `lore/AGENTS.md` text, which is also the text an agent finds in the directory itself. This file adds only what
the session needs beyond that.

If the repository has no `./lore` yet, say so and offer set-up rather than creating a bare directory.

Name the entry with today's date and a short kebab-case name derived from what the user is capturing. One document is a
file; several files are a directory with a `README.md` that says what the entry is, when it went into lore, and which
file to read first. Put the title and orientation line at the top of a file entry. Never overwrite: if the name is
taken, choose a more specific one.

Write the entry from the material the user points at or from the session's own work. Reading other entries is fine when
the new one refers to them; editing them is not. When the material is an existing file elsewhere in the repository that
the user wants moved into lore, move it rather than copying, so no stale copy lingers at the old path, and make sure the
top of the moved file carries the orientation line; it is not frozen until it is in lore.

When copying transcripts, tool output, or logs into an entry, scrub credentials and anything shaped like one, and
anything else the repository's audience should not see; the entry is frozen, so what goes in stays in.

Report the path and stop; whether to commit is the surrounding session's call.
