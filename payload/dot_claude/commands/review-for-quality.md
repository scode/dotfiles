Review the codebase exhaustively. Focus on ways of making the code
higher quality without changing functionality.

- Avoid proposing over engineered solutions.
- Consider readability.
- Consider code which risks future bugs being introduced.
- Consider good abstractions (but again, without over engineering).
- Consider documentation quality when intent is not obvious. Do not
  suggest boilerplate documentation.
- Looks for clear bugs (this is an exception - if fixing a bug, proposing
  changed functionality is fine).

Prioritize and then number the proposed fixes.
